## Decision so far

- **GPU primary (built):** Fast3R, as the brief asks, **for non-commercial academic use only** (C1 answered 2026-10-27). The worker uses it whenever `NAZAR_FAST3R_PYTHON` and `NAZAR_FAST3R_WEIGHTS` are set. Artifacts carry `producer: nazar-worker/fast3r`, and the UI tags them "GPU · Fast3R".
- **Fallback (built, accepted as C3):** the OpenCV baseline. It is used when Fast3R is not configured, or visibly (warning `fast3r_fallback`, with the reason) when Fast3R fails on a job. It is labelled "CPU baseline · sparse SfM" (`producer: nazar-worker/sfm-baseline`).
- Fast3R's archived state is a risk. VGGT remains the alternative, but it would need its own licence decision first.

What this does and does not show:

- Fast3R is **≈ 40× denser** and covers textureless ground that SfM leaves empty. That is the reason to use it.
- **Neither result has ground truth.** There is no scale and no survey, so the table compares density, speed and self-consistency only, not metric accuracy.
- The ≈ 14 s Fast3R geometry stage is mostly start-up: Python and torch import plus model load. Actual inference is ≈ 4.5 s.
- **sample2 exposes the main weakness.** A 6 GB GPU fits 9 views per pass, so 78 keyframes need 15 overlapping passes chained by similarity transforms. Small alignment errors accumulate along the chain, and the camera path shows jumps of up to 13× the median step. On this clip, Fast3R's model confidence never reaches the "observed" threshold, so every point is labelled _estimated_. The UI shows that honestly.
- **A skeleton strategy was tried and not adopted.** It runs one pass over evenly spaced keyframes, then aligns each later pass to that skeleton (`--strategy skeleton`). It halved the worst trajectory jump on sample2 (6.5×) but tripled the alignment residual (median 20 %). It is kept as an opt-in experiment; sequential stays the default.
- **Hypothesis to test on the college GPU (A-series):** with ≥ 16 GB VRAM, sample2 fits in 2–3 passes. That should remove most of the chaining error.

## How the baseline works (for the report)

1. SIFT features (4000 per keyframe, 640 px keyframes).
2. Mutual ratio-test matching within a window of 12 keyframes, then essential-matrix RANSAC.
3. Union-find tracks.
4. Choose the initial pair. Reject near-homographies (planar or rotation-only) and require ≥ 2° median parallax.
5. Incremental PnP registration (EPnP + LM refinement).
6. Triangulate with ≥ 1.5° parallax, ≤ 4 px error and positive depth.
7. Sparse bundle adjustment: analytic Jacobian, Huber loss, shared focal length. The analytic Jacobian is checked against finite differences to 1e-8.
8. Prune, normalise to median camera distance = 10 (unitless), then level the scene with a RANSAC plane fit.
9. A point is **Observed** when seen in ≥ 3 views with ≤ 1 px error, otherwise **Estimated**. The report records the rule.
